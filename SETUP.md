# MarkPro v6 — Local Setup & Hosting Guide

## 0. What's in the box
```
markpro-v6/
  backend/    Node 20 + Express 4 + Mongoose 8 API (all 24 modules)
  frontend/   React 18 SPA (purple Stitch design system)
  scripts/    init-env.js  (generates .env files with secure random secrets)
  docker-compose.yml  one-command stack (mongo + api + web)
```

## 1. Prerequisites
- Node.js 20+ and npm 10+
- MongoDB 6/7 running locally (or a free MongoDB Atlas cluster)
- (optional) Docker Desktop — if you prefer the one-command path

## 2. Local run — manual (recommended first time)

```bash
# a) unzip and enter
unzip markpro-v6.zip && cd markpro-v6

# b) generate .env files with secure random secrets
node scripts/init-env.js

# c) backend
cd backend
npm install
# edit .env: set MONGO_URI (e.g. mongodb://127.0.0.1:27017/markpro)
npm run dev            # http://localhost:5000  (health: /api/health)

# d) frontend (new terminal)
cd ../frontend
npm install
# .env should contain: REACT_APP_API_URL=http://localhost:5000/api
npm start              # http://localhost:3000
```

Create your first account at `http://localhost:3000/register`.
To make it an admin, in mongosh:
```js
use markpro
db.users.updateOne({ email: "you@example.com" }, { $set: { role: "admin" } })
```

### Required env vars (minimum to boot)
| Var | Example |
|---|---|
| `MONGO_URI` | `mongodb://127.0.0.1:27017/markpro` |
| `JWT_SECRET` / `JWT_REFRESH_SECRET` | generated by `init-env.js` |
| `TOKEN_ENCRYPTION_KEY` | 64 hex chars — encrypts all third-party credentials (AES-256-GCM). **Never rotate without re-encrypting.** |
| `FRONTEND_URL` | `http://localhost:3000` |
| `PORT` | `5000` |

Everything else in `backend/.env.example` (Stripe, OpenAI, SendGrid, S3, Meta/WhatsApp, SMM provider keys…) is optional — modules that lack keys simply return a "not configured" error instead of crashing.

### Stripe webhooks (single consolidated endpoint)
```
stripe listen --forward-to localhost:5000/api/webhooks/stripe
```
Put the printed `whsec_...` into `STRIPE_WEBHOOK_SECRET`.

## 3. Local run — Docker
```bash
node scripts/init-env.js
docker compose up --build
# web http://localhost:3000 · api http://localhost:5000 · mongo :27017
```

## 4. Production hosting on your domain

**Option A — one VPS (Ubuntu, ~$6/mo, simplest)**
1. Point DNS: `A  @ -> your.server.ip` and `A  api -> your.server.ip`.
2. On the server: install Node 20, MongoDB (or use Atlas), nginx, certbot, pm2.
3. Upload the project, then:
   ```bash
   cd backend && npm ci --omit=dev
   cd ../frontend && REACT_APP_API_URL=https://api.yourdomain.com/api npm ci && npm run build
   pm2 start ecosystem.config.js && pm2 save && pm2 startup
   ```
4. Use the included `nginx.conf` as a starting point: serve `frontend/build` on `yourdomain.com`, reverse-proxy `api.yourdomain.com` to `127.0.0.1:5000`.
5. TLS: `sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com -d api.yourdomain.com`.
6. Set `FRONTEND_URL=https://yourdomain.com` in backend `.env`, then `pm2 restart all`.

**Option B — managed** (no server admin): frontend → Vercel/Netlify (build `npm run build`, env `REACT_APP_API_URL`), backend → Render/Railway (start `node src/server.js`), database → MongoDB Atlas. Add the same env vars in each dashboard.

Checklist before going live: real `TOKEN_ENCRYPTION_KEY`, live Stripe keys + webhook URL `https://api.yourdomain.com/api/webhooks/stripe`, `NODE_ENV=production`, Atlas IP allowlist, daily `mongodump` backup cron.

## 5. What changed in v6 (Section B fixes)
1. `User.model.js` slimmed to core identity; 14 per-module Profile models added.
2. All third-party credentials encrypted at rest with AES-256-GCM.
3. Four Stripe webhooks consolidated into `POST /api/webhooks/stripe` with one signature verification and metadata-based dispatch.
4. Env vars canonicalised (`FRONTEND_URL`, `MONGO_URI`, `AWS_ACCESS_KEY_ID`, …) across 19 files.
5. Wallet race conditions fixed: atomic `$inc` with sufficiency filters + append-only `WalletLedger`.
6. `backend/.env.example` (102 vars) and `frontend/.env.example` generated.
7. Every API response is `{ success, data | error, message }` via envelope middleware.
8. All routers wrapped for consistent async try/catch + central error handler.
